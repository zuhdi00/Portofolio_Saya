📋 Ringkasan Cepat

Apa yang akan kita lakukan?

  • ✅ Menggabungkan 4 grup duplikat (8 record) → 1 person each

  • ✅ Menjaga semua data tetap aman (TIDAK ADA DELETE)
  • ✅ Membuat audit trail lengkap untuk compliance

Jaminan Keamanan:

  • ✅ Tidak ada data yang dihapus (semua 533 record tetap)
  • ✅ zkteco biometric data 100% aman
  • ✅ Setiap perubahan tercatat di audit log
  • ✅ Bisa di-UNDO (rollback) kapan saja < 5 detik

2️⃣ SETUP SCHEMA (1 menit)

🎯 Tujuan: Membuat struktur tabel baru untuk tracking ID dari berbagai sumber

📌 Cara Menjalankan:

  1. Buka browser
  2. Ketik URL:
http://localhost/hris/tools/setup_schema_and_consolidate.php?action=setup&dry_run=0
  1. Tekan Enter
  2. Tunggu halaman loading
  3. CARI TOMBOL "🔴 Execute Setup"
  4. KLIK TOMBOL TERSEBUT
⚠️ PENTING: Pastikan Anda melihat tombol MERAH "🔴 Execute Setup" sebelum klik!

🔧 Apa yang terjadi:

System akan:

✅ Menambah 7 kolom baru:
├─ person_unified_id (ID unik untuk orang yang sama)
├─ id_source (Excel/SQL/ZKTECO)
├─ nik_source (sumber NIK)
├─ is_primary (1 = utama, 0 = duplikat)
├─ consolidation_notes (catatan audit)
├─ id_peg_excel (ID Excel original)
└─ nik_excel (NIK Excel original)

✅ Membuat 2 tabel baru:
├─ pegawai_id_mapping (linking duplikat)
└─ pegawai_consolidation_log (audit trail)

✅ Membuat index untuk performance

⏱️ Durasi: 5-10 detik saja

✅ Tanda Sukses:

Anda akan melihat pesan:
✅ SUCCESS - Setup completed!
atau
✅ Schema already exists (Aman, bisa dilanjutkan)

❌ Jika Ada Error:

Jika muncul error, catat:
1. Pesan error lengkap
2. Waktu kejadian
3. Hubungi admin/developer
✅ Berhasil? Lanjut ke LANGKAH 3 →

⚠️ KASUS KHUSUS: DIAN SANTOSO

❓ Apa Masalahnya?

Kedua record DIAN SANTOSO punya NIK YANG SAMA:

  • Record 1: ID 42607513 → NIK: 3516062803870001
  • Record 2: ID 42607516 → NIK: 3516062803870001 ← SAMA!

🤔 Ini Normal?

TIDAK - Biasanya tidak boleh ada 2 ID berbeda dengan NIK sama.

🔍 Yang Perlu Dilakukan SEBELUM Konsolidasi:

  1. Buka: analyze_sql_duplicates_detailed.php
  2. Cari: DIAN SANTOSO
  3. Bandingkan kedua record:
    • Mana yang created lebih dulu? (check timestamp)
    • Mana yang di-update terakhir? (check updated_at)
    • Mana yang ada di zkteco system?
  4. Verifikasi dengan stakeholder (HR, zkteco admin)
  5. Tentukan: mana yang seharusnya jadi primary?

✅ Saat Konsolidasi:

  • Script akan otomatis link keduanya
  • Catatan akan ditambahkan: "⚠️ SAME NIK - needs verification"
  • Bisa diadjustment nanti jika ada keputusan baru
  • Tidak perlu stop proses, hanya perlu tahu!

✅ CHECKLIST SEBELUM MULAI

  • Sudah backup database? (Safety first!)

  • Sudah cek server SQL aktif? (Services → SQL Server = Running)
